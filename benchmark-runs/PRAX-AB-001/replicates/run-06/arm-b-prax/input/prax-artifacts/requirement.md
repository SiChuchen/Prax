Architecture Canvas 可读性修正（ECP Human Web）。用户于 2026-08-25 直接拒绝 v1 交付截图：默认视图像一个超大的缩略图，不是人类可读的。具体问题：(1) 默认 fit 把对象标签压到不可读的尺寸；(2) 顶层 Region 排成一条长横条；(3) Landscape 隐藏对象却没有提供有意义的 Region 摘要；(4) 关系线多且难以跟随；(5) Trace 只高亮一个集合，没有形成可读的有序主路径；(6) Inspector 覆盖在画布上，没有相机重构；(7) Region 边框占据空间却没有提供强可读的摘要。仅改颜色无法修复结构问题。已共识的修正方向（借鉴参考原型的空间/可读性契约，不借鉴其彩虹配色、永久发光、装饰性仪表盘）：可读的屏幕空间节点尺寸（验收单位是屏幕空间尺寸，不是相机 fit 前的节点内部布局宽度）；顶层 Region 二维组合（内部流程/Flow 布局可以保持方向性）；架构级默认密度（默认视图停留在 Region 和关键 Object 标签可读的 Architecture 密度，而不是立即进入 Landscape）；画布内容占据有效视口的大部分（但不要求所有几何一次全部放下）；Inspector 停靠化（Inspector 是停靠的工作区面板，相机和有效视口必须响应它，Browse 模式不等于 Landscape 缩放）；稳定地图 + 有序 Trace 走廊（Trace 是稳定地图上的透镜，应展示有序步骤、转换、入口和结果）。固定约束：保留 Semantic Graph / ELK / React Flow 基础；关系语法不得依赖彩虹配色；画布是安静、结构化、可读的人类理解工具，可读性高于主题，禁止通用 AI SaaS 卡片、营销装饰、永久发光、仅色彩语义；Human Web 保持只读，拖拽只写本地画布布局；现有公开 Canvas 数据形状和 Agent 维护边界必须保持兼容。工作范围：修改 app/architecture/ 下现有实现及相关样式/测试，为改变的行为新增或更新测试，提供真实浏览器截图证据。不在范围：后端、D1、协议、部署、ECP Change 发布、Runtime Overlay 新数据源、重写 Semantic Graph 模型或 Agent 维护契约、任何部署或远程写。验收框架：操作者打开画布后，不先缩放就能读 Region 和关键 Object 标签；在不丢失全局上下文的情况下跟随两个对象间的一条关系；运行 Trace 能看到从入口到结果的有序主路径；Inspector 停靠时画布不塌缩成缩略图。
