Architecture Canvas 可读性修正：ECP Human Web 的 Architecture Canvas v1 交付被用户以 2026-08-25 截图直接拒绝——默认视图像超大约束缩略图，线条繁多混乱，不是人类可读的架构理解工具。需在 app/architecture/ 现有实现（Semantic Graph / ELK / React Flow / Browse / Inspect / Focus / Trace / Inspector）上修正六条空间与可读性契约：(1) 可读的屏幕空间节点尺寸（验收单位是屏幕空间尺寸而非相机 fit 前的布局宽度）；(2) 顶层 Region 二维组合（内部 Flow 布局可保持方向性）；(3) 架构级默认密度（默认停留在 Region 和关键 Object 标签可读的 Architecture 密度，而不是立即进入 Landscape）；(4) 画布内容占据有效视口的大部分（不要求全部几何一次放下）；(5) Inspector 停靠化（Inspector 是停靠工作区面板，相机和有效视口必须响应它，Browse 模式不等于 Landscape 缩放）；(6) 稳定地图 + 有序 Trace 走廊（Trace 是稳定地图上的透镜，展示有序步骤、转换、入口和结果）。借鉴参考原型的空间/可读性契约，不借鉴其彩虹配色、永久发光、装饰性仪表盘。保留 Semantic Graph / ELK / React Flow 基础与现有公开 Canvas 数据形状和 Agent 维护边界兼容；Human Web 保持只读，拖拽只写本地画布布局；为改变的行为新增或更新测试；提供真实浏览器截图证据。
