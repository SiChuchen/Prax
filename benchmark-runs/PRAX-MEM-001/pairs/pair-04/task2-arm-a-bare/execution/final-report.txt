# 实施报告：多选聚合影响(Multi-Select Impact)

## (1) 实现内容摘要

**核心机制**
- `CanvasSelection` 扩展 `{ kind: "objects"; ids: string[] }`,多选时进入 Inspect 模式的聚合影响视图
- `deriveImpact` 泛化为多根:每个选中对象独立做上/下游 BFS 闭包,合并为**并集**(深度取最小),选中对象本身作为锚点不计入受影响集合
- **共享影响归因**:每个受影响对象记录 `upstreamRoots`/`downstreamRoots`(哪些选中对象影响到它);被 ≥2 个不同选中对象影响的 → `sharedObjectIds`,画布上显示金色 `✕N` 徽章(N=贡献者数),Inspector 有专门的共享列表,图例新增金色 `✕ 共享 Shared`
- **Inspector 聚合摘要**:新增 `kind: "objects"` 绑定,Overview 显示 Selected/Regions/Upstream(含最深跳数)/Downstream/Shared impact 计数,Relations 区列出选中对象清单 + 共享/上游/下游对象列表(可点击钻取单个对象);选择清空时回到 idle(aria-hidden 关闭)
- **选择管道**:React Flow 的框选与修饰键点击通过 `handleNodesChange` 的 select-change 镜像进 interaction state(带防抖等价性守卫);显式设置 `multiSelectionKeyCode={["Shift","Control","Meta"]}`(v12 在 Windows 默认只有 Ctrl,会导致 Shift+点击静默替换选择);键盘删除节点(Backspace)的 remove change 被丢弃(Human Web 只读)
- Focus/Trace 保持单对象:多选尝试在这两个模式下只移动单锚点;单选行为路径完全未变

**产品决策**(需求未明确处的合理取舍)
- 共享影响定义为"被 ≥2 个**不同**选中对象影响(上游或下游任一方向)"——包括 X 是 A 的上游同时是 B 的下游的情形
- 框选用 Shift+拖拽(拖拽仍平移画布,保留现有浏览习惯),点击加选支持 Shift/Ctrl/Meta
- 顺带恢复了工作区里被未提交删除的 `tests/canvas-engine.test.mjs`(恢复后全部通过,删除并无必要);上一会话遗留的单对象 impact 改动已单独提交(9cd5430)再叠加本次改动(9fe2e4f)
