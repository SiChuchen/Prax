## 1. Summary of what was implemented

Multi-select union impact for the Architecture Canvas, built within the existing Semantic Graph → ELK layout → interaction read model → projection pipeline (boundary, adapter, validation and cache untouched; Human Web still read-only; React Flow/ELK/SmartEdge stack unchanged):

- **Selection model** (`interaction.ts`): `CanvasInteractionState.selectedObjectIds` (ordered set). Plain click selects one object; Ctrl/Cmd+click toggles; Shift+drag marquee (React Flow `selectionKeyCode` default) box-selects. React Flow is the selection source of truth via a new `onSelectionChange` kernel hook; the canvas mirrors it and preserves Trace/Focus behavior.
- **Union + shared impact** (`interaction.ts`): `deriveImpact` now accepts multiple roots — per-root BFS with minimum hop depth across roots, merged per-object roles (`upstream`/`downstream`/`both`), per-relationship roles. Selected roots stay "selected", never "impacted", even when another root reaches them (a bug my first cut had; caught by unit tests). New `contributorCount` and `sharedObjectIds` make "impacted by more than one selected object" an explicit, testable concept.
- **Aggregate Inspector** (`inspector-binding.ts`, `inspector.tsx`): `bindSelectionImpact` produces a summary (selected count/regions, ▲ upstream count+max depth, ▼ downstream count+max depth, ⇄ shared count) plus the full impacted object list sorted shared-first, each row showing role, hops and `⇄ n` contributors, one-click drill-down. With 2+ objects selected the Inspector renders this aggregate panel; emptying the selection returns the Inspector to its idle (closed) state. Single-select keeps the existing object binding and impact summary.
- **Visuals** (`projection.ts`, `architecture-node.tsx`, `globals.css`): shared objects get an amber `⇄ n` chip + border; node data carries `{role, depth, contributors, shared}`; multi-selected nodes render selection rings; reading key shows `⇄ Shared 共同影响` and a selection-aware hint.
- **Camera + integrity**: multi-selection frames the union of roots + impacted in Browse/Inspect only; Focus/Trace framing untouched. Group drags persist every selected object's device-local layout (and only drop routes touching moved objects); `deleteKeyCode` disabled so Backspace can never remove view nodes.
- **Docs**: new "2026-08-31 multi-select union impact" section + acceptance row in `docs/Canvas_Engine_v1_Review.md`; interaction-boundary row in `docs/architecture-canvas-standard-v0.1.md`.

Product decisions made (noted per instruction): aggregate panel replaces the single-object binding when ≥2 objects are selected; roots exclude each other from impacted counts; shared impact is computed over non-root objects; multi-select overlay applies only in Browse/Inspect so Focus/Trace stay literally unaffected. I also restored `tests/canvas-engine.test.mjs`, which was deleted (uncommitted) in the working tree but passes fully and anchors the geometry regression suite.
