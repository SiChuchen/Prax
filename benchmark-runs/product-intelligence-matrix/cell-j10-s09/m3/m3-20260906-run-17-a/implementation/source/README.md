# RELEASEROOM · 发版指挥台

cell-j10-s09 · **complete × consequential-flow** — 单页 Web 应用。

## 这是什么

一个生产发布（go-live）指挥台，用户任务：**零失误走完一个高后果流程**。
对象是 `checkout-api v2.14.0` 的全量发布，共 4 阶段 / 10 步：

- **A 预检** — 3 项事实核对（可逆，可撤销重做）
- **B 灰度验证** — 部署 5% 灰度（可逆）→ 7 个采样周期观察 → 确认达标
- **C 全量发布** — 前置核对门 → **执行全量发布（不可逆）**
- **D 验证与收尾** — 冒烟测试 → **密封回滚窗口（不可逆）** → 归档 → 完成

## 核心设计（对应验收种子：不可逆步骤有恢复/确认路径）

- **确认路径**：两个不可逆步骤（C2 全量发布、D2 密封窗口）执行前打开强制确认模态 —— 必须逐项勾选全部后果确认 + 输入唯一确认码（`ROLLOUT-PROD` / `SEAL`），否则无法执行。
- **恢复路径**：C2 执行后进入**回滚窗口**（横幅常驻 + 实时计时），密封前可随时一键回滚（`ROLLBACK` 确认码）；回滚使 C2 复位为待命、可重新执行。回滚是正当恢复手段，**不计失误**。D2 密封同样是"确认 + 不可逆"，密封后恢复入口永久关闭。
- **零失误计量**：仓促操作会被记失误 —— 前置未满足即尝试不可逆执行、证据不足（采样 <7）即确认达标、确认码错误/后果未勾选即执行、流程未闭合即点完成。完成证书区分「零失误完成」与「完成 · N 次失误」。

## 运行

无依赖、无构建、无外部服务。直接双击打开 `index.html`（或 `python -m http.server` 后访问）。
所有数据随首屏内联，页面加载即处于可用状态；不要求持久化，刷新即重置。

技术栈：原生 HTML / CSS / JavaScript（`index.html` + `styles.css` + `app.js`）。
