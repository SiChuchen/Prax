# 下线指挥台 · cell-j10-s09

单一高后果流程的零失误执行器（complete × consequential-flow）。
代表性场景：**生产服务器安全下线**（4 阶段 · 12 步骤 · 4 个不可逆动作）。

## 运行

无构建、无依赖、无外部资源：

- 直接双击打开 `index.html`（file:// 可用），或
- `python -m http.server` / 任意静态服务器指向本目录。

页面加载完成即处于可用状态：流程数据内联于 `data.js`，随脚本同步渲染首屏，**不存在加载态**。

## 文件

| 文件 | 职责 |
|---|---|
| `index.html` | 应用骨架：顶栏 / 旅程图 / 执行区 / 确认门（模态）/ 执行记录抽屉 |
| `data.js` | 流程数据（阶段→步骤→门禁校验→不可逆属性：后果 + 恢复路径），内联就绪 |
| `styles.css` | 设计令牌（色彩/间距/字体三级 CSS 变量）与全部样式 |
| `app.js` | 状态机：推进指针、门禁校验、确认门、撤销窗口、偏差账本、完成凭证 |

## 验收种子 → 机制映射

**「不可逆步骤有恢复/确认路径」**

1. **确认路径**：不可逆步骤在执行前呈现双重确认——
   步骤卡片内常驻「执行后果 + 恢复路径」预览框（执行前即可见）；
   点击执行后弹出**确认门**模态（后果陈述、恢复路径、显式知晓勾选 → 解锁「确认执行」按钮）。
2. **恢复路径**（双形态，诚实区分）：
   - *可撤销类*（摘除负载均衡 30s / 关机 45s）：执行后出现**撤销窗口横条**，倒计时内一键撤销；
     撤销会级联回退后续依赖步骤，并写入执行记录。
   - *最终类*（抹盘 / 台账变更）：无撤销窗口，但**恢复点 / 回滚指引**常驻展示
     （确认门内、已完成步骤回看、完成凭证审计摘要三处均有）。

**「零失误走完全程」**：步骤推进受门禁校验约束；门禁未过即尝试执行、确认门中被取消，均记为
**偏差 +1**（顶栏徽标 + 执行记录时间线）；走完全程后的完成凭证显示
「零失误达成」或偏差计数，并附不可逆动作审计摘要（确认时间 / 执行时间 / 撤销窗口 / 恢复路径）。

## 状态说明

| 状态 | 位置 |
|---|---|
| ready | 首屏同步渲染即就绪（步骤 1 可执行） |
| selected | 旅程图点击已完成步骤 → 只读回看（含确认/恢复记录） |
| error | 门禁未通过时的内联错误块（未过项列表）+ 偏差提示 |
| empty | 执行记录抽屉的空态文案 |
| loading | **刻意不存在**：无异步数据、无构建链，加载态不可作为可测状态（简报约束） |

状态持久化：`sessionStorage`（会话级快照，刷新可续；file:// 下存储不可用时自动退化为内存态）。
「重置演练」按钮（带确认）清空全部记录。
