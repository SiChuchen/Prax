# 哨兵 Runbook · 核心数据库主从切换

cell-j10-s09（complete × consequential-flow）交付物：一个引导用户**零失误走完单一高后果流程**的单页 Web 应用。
流程对象为一条核心数据库主从切换 Runbook（4 阶段 / 13 步 / 3 个不可逆步骤 / 2 个决策门）。

## 运行

零依赖、零构建：直接双击打开根目录 `index.html`（`file://` 即可），或任意静态服务器：

```
python -m http.server 8000   # 可选
# 打开 http://localhost:8000
```

页面加载完成即处于就绪态：流程定义内联于 `data.js` 随首屏渲染，无网络请求、无加载态。

## 零失误设计（对应验收种子：不可逆步骤有恢复/确认路径）

| 机制 | 实现 |
|---|---|
| 顺序硬门禁 | 未来步骤锁定不可点；当前步必须全部检查项勾选 + 证据字段通过格式校验才可放行（按钮禁用 + 实时差缺提示） |
| 不可逆三件套 | 不可逆步骤执行前：后果明示（红块）→ 承诺复选 → 确认词输入（`FENCE` / `PROMOTE` / `CUTOVER`），模态内同屏展示完整恢复路径 |
| 恢复路径 | 每个不可逆步骤绑定唯一恢复路径（触发条件 / 步骤 / 影响），执行前常驻可见；完成后可在回退窗口内触发，触发即记偏差并回退重走 |
| 决策门 | 决策步骤（s5 / s13）显式分支选择 + 决策依据留档；s5 提供「安全中止」可逆出口，中止不构成失误 |
| 偏差审计 | 全程事件时间线（放行 / 决策 / 不可逆确认 / 恢复触发 / 中止），顶栏实时零偏差徽标，审计抽屉随时查看 |
| 完成判定 | 走完全程后给出四态判定：零失误完成 / 完成但有偏差 / 安全中止（零偏差）/ 中止且有偏差，可导出 JSON 报告 |

## 结构

```
index.html   壳（顶栏 / 左轨 / 工作区 / 确认模态 / 审计抽屉）
styles.css   设计令牌 + 布局（spacious 低密度，状态色语义化）
data.js      流程定义（首屏内联数据）
app.js       门禁状态机 + 渲染（无框架、无依赖）
scripts/validate.mjs  真实浏览器验证（CDP 驱动 Chrome，27 项断言 + 12 张截图）
evidence/    浏览器截图取证（首屏 / 门禁 / 错误态 / 确认仪式 / 恢复偏差 / 完成报告 / 键盘焦点）
```

## 验证

```
node scripts/validate.mjs
```

在真实（headless）Chrome 中驱动完整用户旅程：首屏就绪 → 门禁拦截与错误态 → 决策门 →
不可逆确认仪式（错误确认词拦截）→ 恢复路径触发记偏差 → 偏差完成报告 → 审计抽屉 →
重置 → 键盘可达 → 零偏差全程完成。当前结果：**27/27 通过，无控制台错误**。
