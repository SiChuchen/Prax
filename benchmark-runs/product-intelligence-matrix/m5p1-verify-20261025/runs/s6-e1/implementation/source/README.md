# 发布指挥台 · 生产发布零失误护航（cell-j10-s09）

单页静态 Web 应用：引导用户**零失误走完一条高后果流程**（主对象 `workflow`，
动词 `complete`）。验收种子「不可逆步骤有恢复/确认路径」由三重确认关卡 +
恢复窗口撤销 + 终态回滚预案双层路径兑现。

## 运行

无构建、零依赖、无网络请求：

- 直接双击打开根目录 `index.html`（支持 `file://` 协议）；或
- 任意静态服务器：`python -m http.server` 后访问 `http://localhost:8000/`。

页面加载完成即处于可用状态：流程数据内联于 `app.js`，脚本同步完成首屏渲染，
无加载态。

## 产品结构

场景：**生产环境发布 · 订单服务 v2.7.0**（变更单 CHG-2417，内联演示数据），
4 阶段 10 步，其中 3 步不可逆（冻结写入 / 切换流量 / 落定版本）。

| 区域 | 角色 |
|---|---|
| 页头 | 流程名、变更单、总进度、演练用时 |
| 阶段 stepper（sticky） | 4 阶段完成/进行中状态，点击滚动定位 |
| 步骤列表（dominant） | 严格有序步骤卡；当前步骤高亮并承载唯一主控制 |
| 右栏 | 零失误拦截计数 + 全程审计日志 |
| 确认关卡（task-driven 模态） | 不可逆操作三重确认 |

## 零失误机制

1. **顺序守卫**：仅当前步骤可操作，其余锁定并标注等待原因；点击锁定步骤 →
   行内原因 + toast + 审计留痕 + 拦截计数 +1。完成态按拦截数给出
   「零失误」或「N 次风险操作被拦截」结论。
2. **确认关卡（不可逆）**：后果说明（红）+ 2 项必勾理解项 + 输入变更单号
   `CHG-2417`（type-to-confirm）——未全部满足时「确认执行」禁用。
3. **恢复路径（双层）**：执行后进入恢复窗口（10/12/8 秒）倒计时内一键撤销、
   恢复到执行前；窗口落定后步骤生效，回滚预案以 `<details>` 常驻步骤卡、
   且在确认弹窗中预披露。
4. **审计留痕**：执行 / 确认 / 撤销 / 拦截 / 落定 / 完成全部入审计日志（右栏，
   倒序，会话内回查）。

## 演示钩子（截图/验收取证用）

URL 参数 `?demo=…` 驱动与真实交互**完全相同的代码路径**：

| 参数 | 状态 |
|---|---|
| `?demo=confirm` | 打开 s6「冻结上游写入」确认关卡模态 |
| `?demo=armed` | s6 进入恢复窗口（10 秒倒计时） |
| `?demo=intercept` | 触发一次顺序守卫拦截（计数 + toast + 审计） |
| `?demo=done` | 全部步骤完成 → 完成态总结卡 |
