# 舰队变更史 · Fleet Chronicle

cell-j06-s06（understand × temporal-sequence）交付：一个从零实现的零依赖单页应用，
用于**理解随时间演化的状态**——服务舰队经过 7 个发布窗口（change_set）· 21 项变更 ·
4 条因果链的演化史。变更因果与时间结构互相一致、可读、可验证。

## 打开方式

直接双击打开根目录 `index.html`（file:// 即可，无构建、无外部依赖、无网络请求）。
页面加载完成即为可用状态：数据内联于 `data.js`，首屏默认停在最新窗口（当前状态）。

## 界面（单主屏）

- **左 · 时间轴**：7 个发布窗口按时间排列，含触发事件、变更构成（新增/修改/下线）、
  四项窗口指标（可用率 / p95 / 错误率 / 日成本）；⏮ ◀ ▶ ⏩ ⏭ 支持回放（▶ 为自动回放）。
- **中 · 舰队状态**：选定时刻的服务卡片快照；本窗口发生的字段变更内联显示 `旧值 → 新值`；
  新增服务有"本窗口新增"徽标，下线服务灰显；卡片底部 7 格时间条 = 该服务在各窗口的变更
  （颜色 = 操作类型，点击跳转对应窗口）。
- **右 · 详情**：本窗口变更列表（每项含原因、`↑ 因` 与 `↓ 引发` 链接）；点选任一变更，
  下方展开其**因果链**（因在上、果在下，窗口时间严格递增），"高亮整条链"将跨三栏
  高亮整条因果路径。

键盘：`←`/`→` 切换窗口，`Esc` 退出追踪。

## 时间结构与变更语义一致（验收种子）

- 数据层面：每条因果边 `c.parent` 指向**更早**发生的变更；`modify.from` 必须等于
  该字段在回放到该窗口时的现场值。启动时 `app.js` 会全量校验（因果序 + 语义序），
  结果常驻顶栏徽章：`✓ 时间-因果一致性校验通过 · 21 项变更 · 4 条因果链`，
  同时输出到控制台。
- 指标层面：窗口指标与变更内容对齐（INC-2201 所在 w2 错误率/延迟跳升、网关限流后的
  w3 回落、legacy-report 下线后的 w5 成本下降）。

## 复现交互态（用于外部取证截图）

URL 参数：`?w=<窗口下标>`（0–6）、`&c=<变更ID>`（c01–c21）、`&trace=1`（直接进入
因果链高亮）。例如：

```
index.html?c=c05&trace=1        # INC-2201 通知扩容及其整条因果链
index.html?w=2                  # 事故窗口的舰队状态与内联 diff
```

## 文件

- `index.html` — 页面骨架
- `styles.css` — 暗色主题样式
- `data.js` — 内联数据（目录 / 基线 / 7 窗口 / 21 变更 / 因果边）
- `app.js` — 校验、回放、渲染、交互（无框架、无依赖）
