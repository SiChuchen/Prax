# Realization Providers — agent adapter guide

The `figma_first` realization mode is **representation-first**, not
Figma-only: the mode name is historical. What a provider must actually do is
declared in the registry (`REALIZATION_PROVIDERS`,
`packages/prax-runtime/src/realization.ts`) and every registered provider
offers the same capability triple. This guide tells an agent how to drive
each provider so that `design_realize submit_draft` / `submit_review` accept
its artifacts unchanged. See ADR-004 for the decision record.

## Contract invariants (all providers)

1. **One frame per SDIR region.** The draft's `frames` array must cover every
   region in the representation artifact's `semantic_refs.regions` exactly
   (`validateDraft` checks coverage, unknown regions, duplicate node ids).
2. **Frame name == SDIR region id, byte for byte.** The region id is
   generated by `design_sdir`; copy it exactly (landing run: `hero 区：价值主张
   + 主 CTA（首屏唯一焦点）` — unicode and all).
3. **refs shape is provider-agnostic**: `file_key` = the provider's
   file/document identifier; `node_id` = the provider's object id inside that
   file. Both are opaque strings to Prax.
4. **Evidence**: per-region screenshots saved as real PNG files under the
   session directory at `rep-evidence/round-<N>/<region>.png` (non-empty;
   `validateReview` sha256-verifies them). Approved reviews additionally need
   one `human_decision` evidence item quoting the stakeholder's own words.
5. **Inheritance constraints come from the session**, not the provider: on
   add_surface sessions the approved tokens/shell of the existing surface
   must be reproduced in the new draft with zero drift.

## figma (remote MCP)

- Connect: ZCode user config `mcp.servers.figma` (HTTP + OAuth). `create_new_file`
  needs a `planKey` (team/organization key from `whoami`).
- `file_key` = Figma file key (e.g. `FVsFvRYZyAWv0Z4JXO9tyZ`); `node_id` =
  Figma node id (e.g. `1:2`).
- Build frames with `use_figma` (Plugin API): auto-layout frames, set frame
  `name` to the region id, then screenshot each frame with `get_screenshot`
  into the session's `rep-evidence/round-N/`.
- Known wall: plan-level MCP tool-call quotas (Starter hit it 2026-08-30,
  mid-PRAX-PRICING-001). Switch provider per ADR-004 rather than bypassing.

## penpot (official MCP — self-hostable, no vendor quota)

- Local mode: run `npx @penpot/mcp@stable`, then in the open Penpot file:
  Plugins → Load from URL `http://localhost:4400/manifest.json`, run the
  plugin, "Connect to MCP server" (keep the plugin window open). Client
  config: `{"penpot": {"url": "http://localhost:4401/mcp", "type": "http"}}`.
- Remote mode: enable MCP under account → Integrations → MCP Server, copy
  `https://<domain>/mcp/stream?userToken=<MCP key>` (key shown once). On the
  public SaaS (`design.penpot.app`) some API paths are Cloudflare-restricted;
  a self-hosted instance (docker compose) avoids both that and SaaS quotas.
- `file_key` = Penpot file id (UUID); `node_id` = Penpot shape id (UUID,
  from `high_level_overview` / `execute_code` read-back).
- Write via `execute_code` — it runs plugin-API code on the **currently
  focused page** of the open file (create/rename/move/delete/restyle). Create
  the frames with the region ids as names, populate them, then `export_shape`
  each frame to PNG into `rep-evidence/round-N/`.
- Gotchas: only one browser tab may own the MCP connection; operations hit
  the focused page, so never switch pages mid-build; verify exact tool names
  against `penpot_api_info` on connect (they evolve).

## pen (pen.dev, formerly Pencil.dev — local, design files in repo)

- The MCP server ships with the pen.dev app and runs when the app runs
  (local-only; no cloud dependency). Open the `.pen` file in the app, then
  connect from the agent client — the server registers as `pencil` in
  Codex/Cursor/VS Code MCP lists (see docs.pencil.dev/getting-started).
- `file_key` = the `.pen` file's path or id (it lives in the repo — the
  representation becomes a reviewable, diffable artifact alongside the code);
  `node_id` = node id inside the `.pen` document.
- Write via the `execute` tool (insert / copy / update / replace / move /
  delete; `SetVariables` for tokens; `Get` for read-back) — create frames
  named after the region ids, then use `TakeScreenshot` (inside `execute`)
  for per-region PNGs into `rep-evidence/round-N/`. Read editor/selection
  state with `get_app_state`.
- Gotchas: the app must stay running; design files are git-tracked, so the
  approved representation is committed with the session fixture.

## Choosing a provider

- Default order when Figma quota is unavailable: **penpot self-hosted** (no
  quota, browser-session auth) → **pen** (local, repo-native `.pen` format)
  → wait for Figma quota reset.
- A provider without screenshot capability cannot feed the stakeholder
  approval evidence loop and must not be registered.
- Switching provider mid-session: re-propose `figma_first` with the new
  `provider` before `submit_draft` (same mode → no mode-flip reason needed);
  after refs exist, the normal draft/review lifecycle applies.
